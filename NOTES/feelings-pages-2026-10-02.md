# Feelings pages (shipped 2026-10-02)

What: feelings.html (wheel hero, 22 family cards, family sheet, body map), feelings/<family>.html (22),
feelings-wheel.html (printable poster), css/feelings.css. All GENERATED by scripts/build-feelings.mjs from the
app's src/components/feelingCategories.ts. Never hand-edit the outputs.

Verify after any change:
  node scripts/build-feelings.mjs
  node scripts/check-feelings-page.mjs file://$PWD/feelings.html 1400   (and 390)
The check script fails on: hero below the fold, any printed page taller than Letter, checkbox overlapping a word,
a printed page under 30% full, duplicate ids, horizontal overflow.

Print layout is done by the generator (pack() in build-feelings.mjs), not CSS columns: it packs blocks into columns
from mm estimates, adds "(cont.)" headers, keeps continuations >= 4 rows, moves short lists and mostly-continuation
families whole. If a page overflows, lower MM.pageH or the row estimate; the check script will say which page.

Site stylesheet traps (each caused a bug): `.hero` = min-height 100vh + gradient; `section` = 100px padding;
`nav` = fixed top bar. Do not use those bare names in new markup.

Design: a reviewer subagent scored it 66 -> 77 -> 90 -> 96 -> 98% over five rounds. Colors are family identity,
never good/bad. Family order, colors, one-line descriptions, core words and short wheel labels live in FAMILY.
